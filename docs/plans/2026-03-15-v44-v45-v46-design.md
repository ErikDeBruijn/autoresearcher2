# v4.4 / v4.5 / v4.6 Design

## v4.4: Multi-Project Pipeline

### Problem
System is hardcoded to NanoGPT. Cross-domain "validation" only works with mocks. Need real multi-project support where each project has its own world model, beliefs, and executor — but shares workers, queue, and UI.

### Decisions
- **One database**, `projects` table with foreign keys on queue, observations, world_model
- **Workers claim from all projects**, look up executor by project_id
- **LLM generates executor scripts** via chat — user describes research question, LLM builds the training harness
- **User approves** before project is created and experiments begin
- **Docker sandbox** per experiment — nvidia-container-toolkit for GPU access, dependency isolation per project
- **UI filtering** with checkboxes per project (not dropdown). Running column always visible regardless of filter.

### Schema Changes
```sql
CREATE TABLE projects (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    description TEXT,
    domain_config TEXT,        -- JSON: DomainConfig fields
    executor_script TEXT,      -- generated Python/shell script
    docker_image TEXT,         -- image tag for sandboxed execution
    created_at REAL,
    active INTEGER DEFAULT 1   -- 0 = paused
);

-- Add to existing tables:
ALTER TABLE queue ADD COLUMN project_id TEXT REFERENCES projects(id);
ALTER TABLE observations ADD COLUMN project_id TEXT REFERENCES projects(id);
ALTER TABLE world_model ADD COLUMN project_id TEXT REFERENCES projects(id);
```

### Worker Flow
```
startup:
  for each project where active=1:
    build/pull docker image if needed
    register executor in executors[project_id]

claim loop:
  proposal = store.claim_next_todo(worker_id)  # from any project
  executor = executors[proposal.project_id]
  result = executor(proposal)  # runs in docker container
```

### Chat Project Creation Flow
1. User: "I want to optimize Atari Breakout scores"
2. LLM asks clarifying questions (what metric, what parameters to vary)
3. LLM generates: executor script, DomainConfig, Dockerfile, initial world model beliefs
4. LLM presents plan for approval
5. User approves → project created, docker image built, research loop picks it up

### UI Changes
- Project filter bar with checkboxes (above kanban columns)
- Each ProposalCard shows project name as colored badge
- Running column ignores filter (always shows all running)
- StatsBar shows per-project and aggregate stats
- WorldModelPanel gets project selector (each project has its own WM)

## v4.5: Cost Accounting

### Problem
No visibility into actual energy/money cost of experiments. gpu-cost-tracker service exists on pve03.local:8377 but isn't integrated.

### Integration
Executor wraps each experiment with job start/stop:
```python
# Before experiment
job = httpx.post("http://pve03.local:8377/job/start", json={
    "gpu": cuda_device, "client": "autoresearcher", "label": proposal.id
}).json()

# Run experiment...

# After experiment
cost = httpx.delete(f"http://pve03.local:8377/job/{job['job_id']}").json()
# cost = {energy_kwh, cost_eur, duration_s, avg_power_w}
```

### Schema Changes
```sql
ALTER TABLE observations ADD COLUMN energy_kwh REAL;
ALTER TABLE observations ADD COLUMN cost_eur REAL;
ALTER TABLE observations ADD COLUMN avg_power_w REAL;
```

### UI Changes
- Cost displayed on ProposalCard (done/reviewed): "0.03 EUR, 0.12 kWh"
- StatsBar: total cost, cost per experiment, cost per project
- World model cost_beliefs updated with actual measured costs

## v4.6: Resilience (Survive pve03 Restart)

### Problem
If pve03 reboots, services must come back up and resume research without intervention.

### Requirements
- All systemd services enabled (start on boot)
- gpu-cost-tracker starts before autoresearcher (dependency)
- Docker images survive reboot (persistent)
- SQLite DB on persistent storage
- Startup reclaim (already implemented: timeout_s=0)
- Web UI accessible after reboot without manual steps

### Implementation
- `autoresearcher.service`: After=docker.service cost-tracker.service
- `autoresearcher-web.service`: After=autoresearcher.service
- `cost-tracker.service`: After=network-online.target
- Health check endpoint: GET /api/health returns service uptime + last experiment time
- Watchdog: systemd WatchdogSec for auto-restart on hang
