# v4.1 Web UI — Research Dashboard

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build a web dashboard for autoresearcher2 with kanban board, live worker status, research stats, manual proposal submission, and an interactive chat sidebar for research questions.

**Architecture:** FastAPI backend (Python, same ecosystem as autoresearcher2) serves the existing SQLite Store via REST + WebSocket. React + TypeScript + Tailwind CSS frontend with Vite. Chat sidebar uses claude CLI for research Q&A with world model context. Single `web/` directory in the repo.

**Tech Stack:** Next.js 16, React 19, TypeScript, CopilotKit + AG2 (AutoGen) for chat sidebar, Tailwind CSS, FastAPI backend for research data API

**Reference project:** `~/github.com/erikdebruijn/do.bot-chatui/` — working CopilotKit + AG2 setup with model selector, chat history, voice input. Use this as the foundation for the chat sidebar.

---

## Context

The v4.0 SQLite Store already has:
- `observations` table (append-only reality contact)
- `world_model` table (versioned epistemic state)
- `queue` table (kanban: backlog → todo → running → done → reviewed)
- Atomic claiming (`claim_next_todo`), proposal lifecycle, world model history

The backend wraps this existing Store — no new persistence layer needed.

Erik also wants the GPU box (dllm-experiment.home) running real experiments. The web UI should show live status of workers on that box.

## GPU Utilisation Note

The dllm-experiment VM has Max-Q GPUs (~100W extra per card at full load). It costs almost nothing extra to run experiments. The web UI should make it easy to:
1. See if workers are active (and alert if idle)
2. Submit proposals to keep the queue full
3. Start/stop workers from the UI

### Task 9: E2E browser test — full kanban flow

**Files:**

The E2E test should show the full lifecycle: cards appearing in the first column (generator/backlog), moving to column 2 (critic/todo), column 3 (running), column 4 (done), and column 5 (reviewed/observed). Each observation is analyzed once — the observation step feeds back into the next cycle's orientation.

**Step 1: Write Playwright test**

```bash
cd web/frontend
npm install -D @playwright/test
npx playwright install chromium
```

Test flow:
1. Start FastAPI backend + Next.js dev server
2. Open browser to dashboard
3. Verify 5 kanban columns visible with seeded data counts
4. Submit a new proposal via the form → verify card appears in Backlog column
5. Simulate critic accepting it → card moves to Todo column
6. Simulate worker claiming → card moves to Running column (with pulse animation)
7. Simulate completion → card moves to Done column
8. Simulate orientation/review → card moves to Reviewed column
9. Verify stats bar updates (experiment count, success rate)
10. Open chat sidebar, send a question, verify response arrives

**Step 2: Run test**

```bash
cd web/frontend && npx playwright test
```
